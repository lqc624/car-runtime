# ADR-003 · 插件签名信任根与 enforce 策略（D-1/D-2 裁决实装）

状态: 已定稿（S5 定稿文档；S6 验签器实装）| 2026-09-04

## 决策（D-1）

**双轨签名**：Sigstore keyless 主轨（与发布工程 G-08 cosign / G-09 npm provenance 同源，不另起炉灶）+ minisign 式静态密钥离线轨（解决 R-6 内网/离线验证失败）。

信任锚三层：
1. 内置根：CAR 项目公钥编译期 pinning；
2. Sigstore 链：离线 bundle 验证，禁止运行时拉网（对齐部署侧禁运行时网络下载纪律）；
3. 企业自管替换点：`trustRoot` 配置可替换信任锚，替换动作写审计日志。

## 决策（D-2）

**enforce 时点**：S6 warn 上线（签名缺失 = 告警放行 + manifestHash 指纹兜底）→ S8 末统计 unsigned 占比与误伤率 → S10 发布预演前切 enforce（缺失 = 硬拒绝）。

fail-closed 三情形分级：
| 情形 | M2 行为 |
| --- | --- |
| 签名校验失败（有签名但不对） | 硬拒绝，**不可配置放行** |
| 签名缺失 | S6-S9 warn + 指纹兜底 → S10 enforce 拒绝 |
| Rekor 透明日志不可达 | 回退静态轨；双轨皆败按缺失处理 |

存量已装插件不回溯强制（manifestHash 指纹持续兜底，M3 企业策略项）。Git 直载维持决议⑦告警语义，不纳入 enforce。

## 依据

- 决议⑦：分发 = 目录+签名起步（Shai-Hulud/ClawHub 供应链教训，SR-08/09/14）；
- 部署侧 G-08/G-09 同源复用（M2部署设计增补 T-4）；
- M1 已有 manifestHash 指纹兜底（loader.ts）。

## 回退方案

Sigstore 生态不可用（如 Rekor 长期故障）→ 静态轨独立承载；企业场景 → trustRoot 替换为自管根。验签失败处置遵循安全设计 §4.4 装载前三段。
